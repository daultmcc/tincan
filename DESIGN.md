# TinCan - headphone EQ for Linux

TinCan is a real-time, two-channel, parametric equalizer for Linux, intended primarily for headphone
tuning. It is designed to be simple and ergonomic to use while retaining all the features
necessary for headphone EQ. It is NOT intended as an EQ for input devices or as a plugin
for music production.

## Motivation

The primary existing options for parametric EQ on Linux are Easy Effects, the LSP Parametric
Equalizer, or the equalizer functionality built in to Pipewire. Easy Effects and Pipewire
have inconvenient interfaces for real-time, manual editing, with no visualization of the
resulting curve. The LSP equalizer has a much more ergonomic UI but is not really intended
to be used as a standalone application---it requires manual plumbing via Pipewire to use
and does not support running as a background service. Its GUI also appears to be X11 based
and doesn't handle resolution scaling gracefully. Lastly, it can't load multiple equalizer
presets simultaneously, a feature which would be useful to e.g. keep broad preferential
tonality adjustments separate from narrow resonance correction profiles generated by
Flatiron, or to separate a profile into multiple components which
can be toggled for easy A/B testing.

TinCan is designed to address these deficiencies.

Flatiron is a separate tool (in development alongside TinCan) that measures headphone
resonances by listening tests and fits per-ear bell filters to correct them. Flatiron will
gain an exporter for TinCan's preset format. No deeper integration between the two tools is
planned for now.

## Platform

TinCan is built on Qt and is fully Wayland- and PipeWire-compatible. Ideally it is
written in Rust, but if the ecosystem is deemed suboptimal for this project other
language options can be considered. The intended stack is Rust with a QML UI via
cxx-qt, and `pipewire-rs` for audio.

As noted above, it is currently a Linux application, but where possible architectural
decisions should be made with the possibility of a future macOS version in mind. In
particular the code is split into three layers:

- **Core**: filter math, DSP processing, frequency response calculation, preset model and
  file format. No dependency on Qt or PipeWire.
- **Audio backend**: the PipeWire sink, routing and device handling, behind an interface
  that a future CoreAudio backend could implement. (A system-wide EQ on macOS needs a
  virtual audio device, which is substantially more work than the PipeWire backend.)
- **UI**: Qt/QML windows and the tray element.

## Filter design

TinCan is a real-time, whole system EQ, so it is important that latency is minimized.
It is also intended for use with approximately minimum phase devices (headphones) so
linear group delay should not be critical. As a result TinCan only provides a single
IIR filter mode. Processing adds no latency beyond the PipeWire quantum (no lookahead,
no block-based convolution).

### Filter types

There are three filter types: bell, high shelf, and low shelf. Each is biquad-based and
has three parameters: frequency, gain, and quality factor (Q).

The transfer functions are exactly those of the RBJ "Audio EQ Cookbook" (bilinear transform
with frequency prewarping), which is what Flatiron, Equalizer APO, AutoEQ and PipeWire's
`param_eq` use, so that presets from those tools reproduce exactly.

- **Bell** (RBJ peaking EQ): frequency is the center frequency, gain is the gain at the
  center, Q is the RBJ peaking Q.
- **Low shelf / high shelf** (RBJ shelves, Q form): frequency is the shelf midpoint, where
  the response reaches half the shelf gain in dB. Gain is the full shelf gain. Q = 0.707
  gives the steepest transition without overshoot; higher Q adds a bump and dip around the
  transition. Default Q for shelves is 0.707.

Because the filters are digital, their response depends on the sample rate (most visibly as
narrowing of filters approaching Nyquist). Coefficients are recalculated whenever the
sink's sample rate changes, and all graphs are computed from the actual digital transfer
function at the current rate, so what is shown is what is heard. Matched-magnitude designs
(e.g. Vicanek) would reduce this rate dependence, but would break exact agreement with
other tools; they may be offered as an option later.

### Parameter ranges and defaults

| Parameter | Range | Step (scroll) | Fine step (Shift+scroll) |
| --- | --- | --- | --- |
| Frequency | 20 Hz – 20 kHz, and at most 0.45 × sample rate | 1/24 octave | 1/96 octave |
| Gain | −24 dB – +24 dB | 0.1 dB | 0.01 dB |
| Q | 0.1 – 40 | ×1.05 | ×1.01 |

Frequency and Q step multiplicatively because both are perceived logarithmically. Frequency
input boxes accept suffixes (`1.2k`). A new filter is a stereo bell at 1 kHz, 0 dB, Q 1.0
(or at the clicked frequency and gain, when created by double-clicking the graph). Changing
a filter's type keeps its frequency, gain and Q.

### Processing

- Each filter is realized as a state-variable filter (Simper/Cytomic topology), whose
  magnitude response is identical to the corresponding RBJ biquad but which tolerates
  parameter changes while running without zipper noise or transients. Parameters are
  interpolated across each processing block.
- Filter state and coefficients are 64-bit floats; low-frequency, high-Q filters are noisy
  in 32-bit.
- Each channel runs a cascade of every enabled filter, from every active loaded preset,
  whose channel setting includes that channel, followed by the preamp. Cascaded filters
  commute, so filter and preset order does not affect the sound; ordering in the UI is
  purely organizational.
- Toggling a filter, preset, or global pass-through never switches abruptly. A filter being
  disabled or deleted has its gain ramped to 0 dB (where bells and shelves are exactly
  transparent) over ~20 ms before being removed; enabling does the reverse. Global
  pass-through and preamp changes are likewise ramped.
- The realtime audio thread never allocates or locks. The UI sends parameter updates to it
  through a lock-free channel.
- At most 256 filters can be loaded at once, across all presets.

### Preamp

There is a single global preamp, applied to both channels after all filters. Presets do not
carry a preamp of their own (a per-preset preamp is wrong once presets are stacked, since
the required headroom depends on the combined curve). The preamp has three modes:

- **Match bypass** (default): the preamp is set so that the overall volume with the EQ
  active matches the volume in pass-through, so toggling pass-through (globally or per
  preset) is a fair A/B comparison. The matching gain is the negative of the power
  average of the combined response, averaged across both channels, over 20 Hz – 20 kHz
  with equal weight per octave (i.e. its effect on pink noise). This is an approximation
  of loudness; a perceptual loudness model could replace it later. It updates live as
  filters change.
- **Safe**: the preamp is −max(0, peak), where peak is the highest point of the combined
  response on either channel, so the EQ can never push a full-scale signal into clipping.
- **Manual**: a user-entered value in dB.

In the automatic modes the computed value is shown read-only. Clipping protection:

- **Headroom warning.** When the combined response's peak plus the preamp is above 0 dB
  (always possible in match bypass mode with boosts), the main window's top bar shows a
  warning with the amount, e.g. "+3.2 dB, may clip", with a one-click switch to safe mode.
- **Clip indicator.** The DSP detects output samples above full scale and reports them to
  the UI, which shows a clip indicator in the top bar (held for a few seconds) and an
  alternate tray icon.

## Presets

A preset is a named, ordered list of filters. Each filter has a type, channel (L, R or LR),
frequency, gain, Q, and enabled flag.

### File format

Presets are TOML files, versioned so the format can evolve. This is also the import/export
format, and the one Flatiron will write.

```toml
format = 1
name = "Sundara resonances"

[[filter]]
type = "bell"          # bell | low_shelf | high_shelf
channel = "LR"         # L | R | LR
frequency = 6150.0     # Hz
gain = -4.2            # dB
q = 6.5
enabled = true
```

Unknown keys are preserved where practical and otherwise ignored; a file with a newer
`format` than TinCan understands is refused with an explanation.

### Storage

- Presets: `$XDG_DATA_HOME/tincan/presets/`, one file per preset. The file name is derived
  from the preset name; renaming a preset renames its file.
- Application state: `$XDG_STATE_HOME/tincan/state.toml`.

### Saved and live state

At any given time a preset has at most two states: the **saved** configuration on disk, and
the **live** state in its edit window, if one is open. Only one edit window can be open per
preset; trying to open it again focuses the existing window.

- A loaded preset is heard in its live state if it has an edit window open, and its saved
  state otherwise.
- The preset's name is part of its live state: it can be changed in the edit window, and is
  stored (renaming the file) on the next save.
- A newly created preset has only a live state until it is first saved; nothing is written
  to disk before then. Saving it asks for a name. Closing its edit window without saving
  discards it entirely, unloading it.
- **Save** writes the live state to disk.
- **Save as** writes the live state as a new preset. The edit window then edits the new
  preset, and the original preset's live state is discarded (it reverts to its saved state).
  If the original was loaded, the new preset replaces it in the loaded list, so what is
  heard doesn't change.
- Closing an edit window with unsaved changes prompts to save, discard, or cancel. Discarding
  throws away the live state, so a loaded preset reverts to its saved state.
- Quitting with unsaved changes prompts once, listing the affected presets.

## Audio routing

On start, TinCan creates a stereo virtual sink named "TinCan", makes it the default sink,
and moves all currently playing streams onto it. Its output goes to the selected output
device. On quit, the previous default sink is restored and the streams on TinCan are moved
to it before the sink is destroyed. (If TinCan crashes, PipeWire removes the sink and its
session manager moves the streams to the next default sink, so audio is not lost.)

- Streams that are part of other virtual devices (PipeWire nodes in a `node.link-group`,
  such as filter-chain or loopback nodes) or marked `node.dont-move` are not moved.
- Streams that start while TinCan is running are moved onto it too. A stream the user later
  moves elsewhere stays where they put it.
- The output device list contains every sink except TinCan itself.
- If the selected output device disappears (e.g. headphones unplugged), TinCan outputs to
  the system's fallback sink and says so in the device drop-down. When the selected device
  reappears, TinCan switches back to it.
- The sink follows the graph's sample rate; filters are recalculated on rate changes.

## Persistence

The following are saved in the state file and restored on start:

- Loaded presets and their order, and each one's pass-through state.
- Global pass-through state.
- Selected output device (by PipeWire node name).
- Preamp mode and manual value.
- Window sizes and positions, where the compositor allows.

Autostart is left to the user (e.g. their desktop's autostart settings) for now. `tincan
--hidden` starts without showing the main window, for use in autostart entries. `--no-route`
leaves the default sink and existing streams alone (mainly for development).

## Interface

The TinCan interface has three components: a **tray element** present whenever the application
is running, a **main window** for global options, and an **edit window** for editing
a single preset. When started, it creates a "TinCan" Pipewire sink which is destroyed on
exit (see Audio routing).

TinCan is single-instance. Closing windows leaves it running in the background. Launching it
again while it's running shows (or focuses) the main window, which is how the main window is
reached on desktops without a system tray (e.g. stock GNOME).

### Tray element

Left-clicking the icon in the tray opens the main window, or focuses it if it is already open.
Right-clicking it opens a menu with two items: "Activate"/"Deactivate", to toggle
global pass-through of the filter, and "Quit" to completely quit the application. The icon
indicates whether TinCan is active, bypassed, or has recently clipped.

### Main window

The functions of the main window are: managing presets, toggling pass-through, selecting
the output device, setting the preamp, and showing the frequency response curve of the
combined filter.

The output device selection drop down, pass-through toggle, preamp controls (mode and value),
and headroom/clip indicators are in a bar at the top of the window. Below that is the
frequency response graph, showing the combined response of all active loaded presets
(excluding the preamp), with separate L and R curves when they differ. Further down is a
list of all currently loaded presets, each of which has an individual pass-through toggle
and a button to unload the preset entirely. Double-clicking a preset opens it in an edit
window. There's
a button to add new presets which opens a drop-down, with one option to create a new
preset along with all the saved ones not already loaded. If the create option is
selected, it immediately opens the new preset in an edit window, as well as loading it. The
new preset isn't saved until the user saves it (see Saved and live state).

At the bottom of the window are a button labeled "Manage presets", which opens a modal
where existing presets can be deleted, renamed, or opened in an edit window (without
loading them immediately), and has buttons to import or export preset files to other
locations on the system; and a "Quit" button which quits the application entirely.

- Deleting a preset that is loaded or open in an edit window asks for confirmation, then
  unloads it and closes its edit window.
- Importing a preset whose name already exists prompts to rename or replace.

### Edit window

The edit window allows an individual preset to be adjusted by hand. Any number of edit
windows can be open simultaneously for different presets (but only one per preset), and
adjustments to loaded presets take effect immediately. However, changes are not persisted
until explicitly saved (see Saved and live state).

The interface is loosely similar to the LSP equalizer's. At the top of the window is
the name of the open preset (marked when there are unsaved changes; double-click it to
rename), "Save" and "Save as" buttons, and, if the preset is loaded, a pass-through toggle tied to those on the main
window. (If the preset is not loaded the toggle is grayed out.) Underneath is a frequency
response graph, showing both the cumulative response of this preset and the response of
each individual filter, with separate L and R cumulative curves when they differ. Also
corresponding to each filter is a dot representing the frequency and gain (for shelves, the
dot sits at the full shelf gain, above or below the curve's midpoint). The dots and
individual filter curves are color-coded. Dots can be dragged (horizontally for frequency,
vertically for gain) and selected (which has the effect of highlighting the corresponding
box at the bottom of the screen, described below). Pressing Backspace or Delete with a dot
selected deletes the filter, and double clicking on the graph creates a new filter with a
dot at that location. Scrolling with a filter selected changes Q. Hovering a dot enlarges it
and adds a soft halo, as does hovering its filter's box; the selected and hovered dots are
labelled with their filter numbers.

The graph spans 20 Hz – 20 kHz on a log axis, with a gain axis that fits the curves but
never shows less than ±12 dB.

Below the graph is a scrollable list of all the filters and their parameters, arranged
horizontally. Each filter is shown as a tall, narrow box. Its top row has the filter's
number on a handle in its color (dragged to reorder), an on/bypassed toggle and a delete
button. Below are a mode drop down (Bell, High shelf, Low shelf), a channel selector (L, R,
or LR), and input boxes for frequency, gain, and Q (labelled "Sharpness (Q)"). Hovering
these boxes and scrolling adjusts them (see Parameter ranges and defaults for step sizes). The filters can be re-arranged by dragging, and there is a
button to sort them by frequency. There is also a button to create a new filter, which is
by default a stereo bell filter.
